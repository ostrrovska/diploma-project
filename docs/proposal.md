# Thesis Proposal

## Попередня робоча назва проєкту

**Українською:** Алгоритми динамічного ціноутворення та конкурентного бронювання в B2C-маркетплейсі

**English:** Dynamic Pricing and Concurrent Booking Algorithms for a B2C Marketplace

## Актуальність та проблематика

Заклади харчування та ритейл втрачають до 6% обороту через списання товарів з обмеженим терміном придатності. Наявні цифрові рішення перерозподілу (за типом Too Good To Go) реалізують статичну модель «сліпих пакунків» із фіксованою знижкою наприкінці дня: вона не враховує поточний попит, не створює цінового стимулу до раннього викупу та не гарантує коректності обробки під час високого одночасного навантаження в момент розпродажу обмеженої кількості лотів.

Інженерна складність задачі полягає в поєднанні в межах однієї системи трьох взаємопов'язаних підзадач: розрахунку ціни в реальному часі як функції часу до закриття закладу; обробки лімітних (відкладених) ордерів на купівлю; та гарантовано коректного бронювання лота під час конкурентного доступу сотень користувачів без подвійного продажу. За характером ця задача ближча до біржового мікро-аукціону, ніж до типового CRUD-функціоналу.

## Сформована ідея продукту (тип архітектури)

Кросплатформний мобільний застосунок з геопросторовими сервісами, підкріплений мікросервісним бекендом реального часу для динамічного ціноутворення та конкурентного бронювання лотів. Система становить B2C-частину двостороннього маркетплейсу перерозподілу товарів і взаємодіє з незалежною B2B-системою (тема командного партнера) через REST API-контракт, зберігаючи власну архітектуру, базу даних і клієнтський застосунок.

## Детальний опис функціоналу (Core Features)

1. **Алгоритм динамічного ціноутворення (Price Decay)** — нелінійна функція зниження ціни лота залежно від часу до закриття закладу, з фоновим плановим перерахунком.
2. **Механізм лімітних ордерів (автовикуп)** — фонове відстеження ціни та автоматичне виконання транзакції при досягненні порогу, заданого користувачем.
3. **Захист від подвійного продажу (конкурентне бронювання)** — транзакційне блокування на рівні бази даних (`SELECT FOR UPDATE SKIP LOCKED`) для коректної обробки одночасних запитів на купівлю останнього лота.
4. **Геопросторовий пошук і кластеризація** — пошук закладів за радіусом та кластеризація територій (PostGIS, `ST_ClusterDBSCAN`) для візуалізації на карті.
5. **Рушій гейміфікації та статусів** — розрахунок балів впливу, ієрархія титулів, щоденний decay-пайплайн для утримання активності користувачів.
6. **Мобільний клієнт реального часу** — WebSocket-оновлення цін без polling-запитів, кошик, профілі гравців, інтеграція інтерактивної мапи.
7. **Інтеграційний REST API-контракт із незалежною B2B-системою** — прийом фіду опублікованих лотів і передавання підтверджень транзакцій.

## Попередній інструментарій та технологічний стек

| Категорія | Технології |
| --- | --- |
| Мови програмування | TypeScript |
| Архітектурні патерни | Мікросервісна архітектура, REST API, транзакційне блокування (SKIP LOCKED) замість розподілених локів, event-driven оновлення через WebSocket |
| Фреймворки | NestJS (бекенд), React Native (Expo) або Flutter (мобільний клієнт) |
| Бази даних | PostgreSQL з розширенням PostGIS; Redis (кеш і pub/sub для масштабування WebSocket) |
| DevOps-інструменти | Docker, RabbitMQ/BullMQ (черга фонових задач), GitHub Actions (CI/CD) |
